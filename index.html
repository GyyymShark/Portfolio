🔧 성능 개선 사례

01. 메인페이지 속도 개선
문제
메인페이지 초기 로딩이 매우 느려 사용자 체감 속도가 크게 저하
(Lighthouse 측정 기준 FCP 27.7s · LCP 66.5s)
무거운 정적 파일(JS 2,379KB · CSS 1,012KB)과 메인 히어로 영역의 CSR 렌더링이 초기 그리기 지연의 주요 원인
시도
① webpack 코드 스플리팅으로 main_fcp.js · main_fcp.css 등 정적 파일을 초기 진입에 필요한 청크 단위로 분리해 다운로드 · 파싱 비용 절감
② 첫 화면을 좌우하는 메인 히어로 영역을 CSR → SSR로 전환해 의미 있는 콘텐츠를 서버에서 선렌더링
결과
지표 AS-IS TO-BE 개선율
JS 파일 크기 2,379KB 1,056KB 55.6% ↓
CSS 파일 크기 1,012KB 497KB 50.9% ↓
FCP (초기 출력) 27.7s 18.7s 32.5% ↓ (9s 단축)
LCP (최대 요소) 66.5s 57.7s 13.2% ↓ (8.8s 단축)
배움
"무엇을 줄일까"(정적 자원 용량)와 "언제 그릴까"(렌더링 시점) 두 축을 함께 다룰 때 Core Web Vitals 개선 효과가 가장 크다
02. 상품진열 프로시저 쿼리 튜닝
문제
프로시저내 로그 테이블 접근 힌트가 INDEX SKIP SCAN을 일으키며 BUFFER 증가
시도

결과

배움
잘못된 힌트는 성능저하를 유발할 수 있다
03. 장바구니 담기 속도 개선
문제
장바구니 담기 동작 시 "함께 구매하면 좋은 상품"을 노출하는 로직이 OD_ORDER_WITHBUY_ITEMS 테이블을 조회
현재는 화면에서 사용되지 않는 로직이지만 호출부가 남아 있었고, 해당 테이블에 데이터가 대량으로 적재되어 장바구니 담기 응답 속도를 저하시킴
시도
커밋 히스토리 · 호출부 · 화면 사용처를 추적해 해당 로직이 더 이상 노출되지 않음을 확인
영향도가 없다고 판단 후 레거시 호출 로직 제거
결과
장바구니 담기 동작 속도 최대 5초 → 2초로 단축
배움
UI에서 사라진 기능이라도 호출부가 남아 있다면 비용은 그대로 발생한다. 레거시 제거 전에는 반드시 사용처 · 영향도를 추적해 안전하게 걷어내야 한다
04. 매거진 쿼리 튜닝
문제
매거진 콘텐츠 리스트 페이지에 인기순 · 최신순 · 추천순 정렬이 있었고, 인기순은 콘텐츠별 조회수를 기준으로 동작
조회수 기준 테이블이 UR_ACCESS_URL_LOG_2025였는데, 이 테이블은 콘텐츠 정렬 전용이 아닌 유저 접속 로그 누적 테이블이라 데이터량이 방대
SGA 캐시에 적재된 동안에는 1~2초대였지만, 하드파싱이 발생하면 15초 이상 소요
시도
마케팅 기획자와 해당 정렬 조건이 실제로 필요한지, 대체 · 변경할 의향이 있는지 협의
정렬 조건 제거로 합의하여 UR_ACCESS_URL_LOG_2025 접근 로직 제거
결과
간헐적 15초 → 상시 1초로 개선
배움
쿼리 튜닝이 항상 SQL · 인덱스 차원에서만 풀리는 것은 아니다. 기획자와 요구사항을 다시 합의해 비용 자체를 없애는 것이 더 본질적인 개선이 될 수 있다
05. AI OCR 기반 상품정보 정합성 검증
문제
상품 등록 담당자가 라벨 이미지를 보고 중량 · 열량 · 보관방법 등을 어드민에 수기로 입력해 오등록 가능성이 있었고, 전체 상품을 지속적으로 검수할 자동화된 수단이 부족
월 5건 이상의 불일치가 여러 검수 경로에서 발견되어, 오류 탐지부터 담당자 전달까지의 자동화가 필요
시도
Azure OCR로 상품 라벨의 텍스트를 추출하고, OpenAI API로 중량 · 총열량 · 보관방법 등 검증값을 구조화
정기 배치에서 어드민 등록정보와 비교한 뒤 불일치를 저장하고 Teams 알림을 전송
AI의 의미 추출 후 필드별 우선순위 · 예외 규칙 · 응답 형식 검증을 적용해 오탐을 제어
결과
